01业务小哥的烦恼

👨‍💻
业务小哥
我想调个 DeepSeek 写总结、调个 Claude 做评审……结果发现三家 API 说三种"方言"！
🎩
Responses 协议
system 请放 instructions，上限叫 max_output_tokens～
🥷
Anthropic 协议
system 要放顶层参数！还要 x-api-key 头！max_tokens 必填！
🧧
Chat 协议
俺们 system 放 messages 里，流式要 stream_options 才给 usage～
👨‍💻
业务小哥
😭 每家的字段名、鉴权头、流式事件、错误格式全都不一样，我的代码里已经 if/else 满天飞了……
知识点：这就是"协议不兼容"——需要一层防腐层把差异挡在业务之外。对应代码 adapters/ 三个适配器。

02公司开张：一张菜单走天下

📋
统一协议
别慌！本公司只提供一张菜单：model / messages / response_format / temperature / top_p / max_tokens / stream
👨‍💻
业务小哥
就这 7 个字段？就能用所有模型？
📋
统一协议
对，这是所有主流 LLM API 的公共最大交集。你写一次，我们翻译成各家方言。
知识点：统一调用协议 UnifiedRequest（contracts.py）——业务层永不接触上游原始报文。

03三位翻译官：适配器模式

👨‍💻
业务小哥
这是我的请求，请给我 deepseek-v4-pro 的回答。
🎩
Responses 翻译官
收到！system 搬进 instructions，结构化输出走原生 json_schema（硬约束）。
🥷
Anthropic 翻译官
到我这儿没有结构化字段，我把 Schema 写进 system 说服模型（prompt_only 降级档）。
🧧
DeepSeek 翻译官
俺是中间档：开 json_object 保语法 + Schema 注入保语义（json_mode）～
📋
统一协议
无论谁接单，回给你的都是同一种格式（ModelResult / 事件流）。换供应商？改一行配置。
知识点：适配器模式 + 注册表（ADAPTER_REGISTRY）。新增协议 = 1 个子类 + 1 行注册，业务层零改动（开闭原则）。

04前台领班：模型路由

🧭
Router 领班
客人点名 deepseek-v4-pro？我查路由表——主路由 Responses 官，备路由 Anthropic 官。
👨‍💻
业务小哥
为什么要备用的？
🧭
Router 领班
主官病了自动换备官（fallback）；忙不过来还能按权重分流（负载均衡）。全楼谁身体不好，我都记在小本本上。
知识点：ModelRouter（router.py）——别名路由、priority/weighted_random 两策略、熔断状态记录。

05门口三兄弟：限流 · 重试 · 熔断

🎫
令牌门卫
进门先领令牌！桶里就 10 个，每秒补 1 个——管你多急，超速就请回（429）。
⏳
重试大叔
上游 429/超时/5xx？别急，我指数退避地重试：0.5s → 1s → 2s，还得抖一抖（jitter），免得大家同一毫秒冲上去把刚醒的上游又撞晕。
🛡️
熔断保安
同一家连败 3 次？拉闸！冷却 20 秒内一个请求都不许送过去——快速失败，别陪葬。
👨‍💻
业务小哥
那 401 密码错、输入超长这种"注定失败"的呢？
⏳
重试大叔
那种我一次都不重试（retryable=False）——但会问问隔壁备官愿不愿意接（换路由的 Key 可能是对的）。
知识点：稳定性三件套各管一时段——限流管常态、重试管瞬时故障、熔断管持续故障（rate_limit.py / retry.py / router.py）。

06质检员与改作业的老师：结构化输出

🔍
质检员
模型说输出 JSON？我不信。不管上游承诺了什么，我都本地再验一遍：语法 + JSON Schema 逐条核对。
🤖
模型
呜……我交了 {"name": 123}，name 要求字符串……
✏️
修复老师
来，这是你的错题详情——哪条不对、Schema 是什么都给你，在原文基础上改，别从头重写（修复循环）。
🤖
模型
{"name": "Ada"} ✅
知识点："不信任上游"原则——本地始终校验（structured.py）；校验失败进修复循环（喂回错误详情重发，service.py），耗尽才抛 422。

07直播员：流式输出

📺
直播员
等全部写完再给你？太慢了！我边生成边播：start → delta → delta → … → end。
👨‍💻
业务小哥
那 JSON 还没写完怎么校验？
📺
直播员
播归播，验归验——我先转发碎片（你看打字机效果），流结束再整体校验，合格就补发一个 structured 事件。
⏳
重试大叔
提醒：直播开始后（第一个字已播出去）我就不重试了——重播会让观众看到鬼畜的双重内容！
知识点：SSE 类型化事件协议（start/delta/structured/end/error）+ "不可撤回"语义（首 delta 后不重试）+ TTFT 首 token 指标。

08监控室、档案馆与安检口

👁️
监控室
每次调用都记档案：request_id 贯穿全程，tokens/延迟/首token/重试/降级/错误率，按模型和供应商随时查账。
📚
档案馆
Prompt 当代码管——版本只增不改，随时 diff、随时回滚，线上行为永远可复现。
🛂
安检员
用户输入里藏"忽略以上指令"？先打包贴标签（<untrusted_data> 包裹），输出敢泄漏系统提示词？直接没收（403）！
知识点：可观测性（observability.py）、Prompt 版本管理（prompts.py，含 Jinja2 沙箱 + StrictUndefined）、注入防护两道防线（security.py）。
