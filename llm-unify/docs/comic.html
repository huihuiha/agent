架构

01防腐层 Anti-Corruption Layer

👨‍💻
新人
为什么我的业务代码里全是 if provider == "anthropic"？
🏛️
架构师
因为别人家的概念渗进了你家的代码。在边界上建一层翻译，外部概念到此为止——这就是防腐层。
👨‍💻
新人
判断标准是什么？
🏛️
架构师
搜一下你的代码，出现 instructions、x-api-key 这种外部词汇，防腐层就漏了。
知识点：统一协议 = 各外部系统的公共最大交集（7 个字段）；业务只依赖自己的语言。 案例落点：contracts.py 的 UnifiedRequest。 DDD 里的经典战术模式；同样适用于支付网关、多云存储、第三方登录。问"怎么隔离第三方 SDK"时就是考它。
设计模式

02适配器 + 注册表 Adapter & Registry

🎩
翻译官 A
我只会 Responses 方言，别的不接。
🥷
翻译官 B
我只管 Anthropic 方言。
📇
注册表
客人报个 protocol 字符串，我查表派一位。新来一位翻译官？登记一行就能上岗——没人需要改老代码。
知识点：开闭原则——对扩展开放（加子类+注册一行），对修改关闭（业务/路由层零改动）。接口用抽象基类强制（ABC），差异全部压进子类。 案例落点：adapters/base.py + ADAPTER_REGISTRY。 GoF 23 模式里出镜率最高的一对；配合"组合优于继承"（公共逻辑放基类、差异放子类）一起讲。
错误处理

03用类型编码处理策略 Typed Exceptions

👨‍💻
新人
catch 里写 if "timeout" in str(e) 判断要不要重试……
🏛️
架构师
住手！字符串匹配会碎。让异常类自己携带策略：retryable、HTTP 状态码、退出码——上层只读属性，永不罗列清单。
🔒
401
我不可重试。
⏰
429
我等一会就好。
📏
超窗
重试一万次我也这样。
知识点：错误分类学——瞬时 vs 确定决定可重试；谁的错决定 HTTP 码（4xx 客户端/5xx 服务端）；基类默认不可重试（宁漏勿滥）。 案例落点：exceptions.py，重试层只剩 if not exc.retryable: raise。 所有网关/中间件的面试题：错误该在哪一层处理？答案永远是"谁有信息谁决策，类型负责传递信息"。
稳定性 1/3

04指数退避与抖动 Backoff & Jitter

⏳
重试大叔
失败了别马上撞，0.5s → 1s → 2s，指数拉大间隔——故障恢复时间未知，别在人家最虚的时候冲。
👨‍💻
新人
大家都退避 1 秒，不就同一毫秒一起冲回去了？
⏳
重试大叔
好问题！这叫惊群。所以退避要乘随机抖动（±25%），把"精确同时"打散成区间分布——实测 10 个客户端同时重试，峰值并发从 10/10 降到 8/10。
知识点：重试的前提是幂等；放大系数 = 次数×层数（客户端×网关×SDK 会叠成 27 倍流量），所以重试只在一层做。 案例落点：retry.py（退避封顶 + 抖动；sleep 可注入假时钟）。 AWS 架构博客与 Google SRE 的经典题；进阶追问：full jitter vs bounded jitter、重试预算（retry budget）。
稳定性 2/3

05熔断器 Circuit Breaker

⏳
重试大叔
我最怕持续故障——重试只会把刚恢复的上游再撞挂。
🛡️
熔断保安
那是我的活：闭合 → 打开 → 半开。连败 3 次就拉闸跳过它；冷却 20 秒后放一个试探请求；成功即复位，失败再拉闸。
👨‍💻
新人
分工是？
🛡️
熔断保安
重试管瞬时故障，熔断管持续故障——毫秒级抖动交给大叔，分钟级宕机交给我。
知识点：核心价值是快速失败——故障期间不再浪费超时时间去撞墙；注意它是有状态的（进程内存态，重启清零）。 案例落点：router.py 的 CircuitState 三态。 微服务三件套（重试/熔断/超时）的面试必考；进阶：熔断窗口的统计口径（滑动窗口 vs 连续计数）。
稳定性 3/3

06令牌桶限流 Token Bucket

🎫
门卫
我的桶能装 10 个令牌、每秒补 1 个——允许突发，稳态收敛。没令牌？429 请回，附上建议等待秒数。
👨‍💻
新人
要后台线程一直补令牌吗？
🎫
门卫
不用，惰性补充：取令牌时按时间差一次补足——零线程，纯计算。
知识点：为什么选令牌桶不选固定窗口？窗口算法在边界有双倍尖峰；漏桶强制匀速牺牲突发。单机用进程内桶，多副本必须换 Redis（接口不变，实现换）。 案例落点：rate_limit.py。 限流三算法对比是高频题；追问点：分布式限流、分层限流（网关+供应商配额）。
可靠性

07信任边界与自纠错 Trust Boundary & Repair Loop

🔍
质检员
上游说"我保证输出 JSON"？我不信。校验权必须在自己手里——这是网关对下游的唯一硬承诺。
✏️
老师
不合格别扔，把错题详情喂回去让它改——"name 要 string 你给了 123"。这叫修复循环：带着上下文订正，比从零重写省且稳。
👨‍💻
新人
这个思想还能用在哪？
🔍
质检员
任何概率性输出：代码生成后跑测试、失败信息回喂模型重改——Agent 自我修正的通用骨架。
知识点：能力分级降级（原生 schema → json_mode → prompt_only）；"不信任上游"= 永远本地校验；修复循环是 LLM 时代的重试变体——重试重发同样请求，修复重发更好的请求。 案例落点：structured.py + service.py:_dispatch_with_structured。 Agent 工程的核心模式之一（self-correction / reflexion）；面试问"LLM 输出不稳定怎么办"的标准答案。
交互

08流式的代价：不可撤回 Streaming & Irrevocability

📺
直播员
首 token 延迟（TTFT）比总延迟更影响体验——所以我边生成边播，事件协议统一成 start/delta/end。
👨‍💻
新人
播到一半上游挂了呢？重试呀？
📺
直播员
不能。已经播出去的字收不回来，重发观众会看到鬼畜。所以流式的重试窗口只存在于首帧之前——这是流与非流在容错设计上的根本分叉。
知识点：SSE 协议（POST+流式读取，DevTools 对 POST-SSE 显示为空是浏览器限制）；生成器惰性求值天然背压；不可撤回语义改变一切容错决策。 案例落点：service.stream 的 emitted 标志。 SSE vs WebSocket 选型（单向 vs 双向、断线重连）；流式场景的取消、checkpoint、事件重放是进阶题。
LLM 工程

09Prompt 即代码 Prompt as Code

📚
档案馆
Prompt 是行为契约，改一个词行为就变——所以它配得上代码的待遇：版本号、diff、回滚、不可变历史。
👨‍💻
新人
渲染用户传来的模板字符串，有风险吗？
📚
档案馆
有！模板里写 {{ ''.__class__ }} 能逃逸执行代码——要沙箱渲染；变量缺失要立即报错而非静默产出半成品（StrictUndefined，fail-fast）。
知识点：版本不可变（只 INSERT 不 UPDATE，diff 永远稳定、行为可复现）；SSTI 攻击与沙箱；fail-fast 哲学。 案例落点：prompts.py（SandboxedEnvironment + StrictUndefined）。 类比数据库 migration / API 版本管理；"prompt 变更如何回归"是 LLM 平台团队的核心痛点。
安全

10当指令和数据共用一种语言 Prompt Injection

🛂
安检员
SQL 时代有参数化查询这个银弹，因为代码和数据语法可分离。但 prompt 是自然语言——指令和数据共享同一个表示空间，没有语法边界。
👨‍💻
新人
那怎么防？
🛂
安检员
纵深防御：不可信数据贴标签包裹（输入侧）＋ 扫描系统提示词泄漏（输出侧）＋ 角色特权分级 ＋ 权限最小化。全是降险，没有根治——这是 OWASP LLM Top 1。
知识点：注入危害上限 = 被劫持输出能触发的副作用上限（模型只输出文本时最坏是"说错话"，接上工具就是"删库"）——所以权限最小化才是真护城河。 案例落点：security.py 两道防线。 Agent 安全的入口话题；间接注入（恶意指令藏在网页/文档里）是工具调用场景的主战场。
工程实践

11可测性是设计出来的 DI & Mock Transport

👨‍💻
新人
79 个测试不花一分钱、不打真实 API，怎么做到的？
🧪
测试
两步：① 组合根——全部对象在一个工厂函数里装配、依赖从构造器注入，测试就能换掉任何零件；② MockTransport——替换 httpx 传输层，截获真实序列化后的请求做断言（比 mock 对象方法强：连序列化 bug 都能抓）。
🏛️
架构师
记住：可测性不是测试技巧，是架构属性——测不了，说明依赖被焊死了。
知识点：组合根（Composition Root）＝全项目唯一 new 的地方，15 行装配代码就是架构文档；fixture 工厂模式组装任意故障场景；"fake 模式"让无 Key 环境也能演示全链路。 案例落点：runtime.py:build_service + tests/conftest.py。 "怎么测调了外部 API 的代码"是通用面试题；DI 的价值一句话——把"环境问题"和"逻辑问题"分开。
