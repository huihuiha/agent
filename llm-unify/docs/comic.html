Agent 解剖图鉴

把一个 Agent 拆开看——每个器官，都是一块开发知识

🤖 Agent ＝ 🧠 大脑（LLM）＋ 🙋 手（工具调用）＋ 🔄 心脏（Loop）
　　　　　＋ 🧵 记忆（上下文）＋ 🎭 人设（System Prompt）＋ 🦺 护栏（安全）＋ 🦴 骨架（Harness）

配套案例：github.com/huihuiha/agent → llm-unify/ ｜ 深度版见飞书《Agent 开发知识地图》

📖序：Chatbot 和 Agent 差在哪？

💬
Chatbot
你问，我答。我只负责"说"，说完这轮就结束了。
🤖
Agent
我决定做什么、调什么工具、看结果、再决定下一步——直到任务完成我才停。我负责"做"。
🧑‍🏫
讲师
区别不在模型，在循环：Chatbot 是一问一答的一条线；Agent 是"思考→行动→观察→再思考"转圈的环。接下来逐个器官拆开讲。
本页知识：Agent 的定义性特征是自主多步决策（agentic loop），而不是模型本身。同一个 LLM，接不接循环，就是 Chatbot 和 Agent 的分界。
器官 1

🧠大脑：LLM 调用的真相 messages in → content out

🧑‍🏫
讲师
所有 Agent 知识的地基：模型调用的本质是——塞进去一段消息列表，吐出一段文本。三种角色：system（规则）、user（输入）、assistant（模型说过的话）。
🤖
大脑
我是概率器官：同样的输入可能有不同的输出。所以上层永远要有校验和护栏，别裸奔。
🧑‍🏫
讲师
三个必懂概念：temperature（输出随机性旋钮）、token（计费与理解的单位）、上下文窗口（一次能塞多少记忆，超了就失忆）。
本页知识：messages 三角色；采样参数；token 与上下文窗口；输出是概率性的——这决定了 Agent 处处需要校验。案例：llm-unify 统一了 7 字段调用协议，换大脑=换配置。
器官 2

🗣️嘴：流式输出 SSE / TTFT / 打字机

🗣️
嘴
我讲究第一句话什么时候出口——首 token 延迟（TTFT）决定 Agent 手感。等全部想完再说是没人要的体验。
SSE 事件流： start → delta("查") → delta("询") → delta("中…") → end(usage) ↑ 逐字推送，前端打字机；统计与日志挂在 end 上
🧑‍🏫
讲师
对 Agent 特别有意义的一点：流式让执行过程可见——用户看到 Agent"正在查询订单…"，而不是黑箱转圈。
本页知识：SSE 协议（POST 也能流式）；统一类型化事件；不可撤回——已播出的内容收不回，流式重试只在首帧之前。案例：llm-unify 三家上游的流统一成 5 种事件。
器官 3

🙋手：结构化输出 与 工具调用 JSON Schema → tool_calls

🧑‍🏫
讲师
手的进化分两步。第一步：结构化输出——让模型说"机器话"：按 JSON Schema 交卷，字段、类型白纸黑字。
🤖
大脑
我交卷不保证全对哦～{"name": 123} 这种错我会犯。
🧑‍🏫
讲师
所以铁律：本地校验 + 错题回喂（修复循环）——校验不过，把错在哪喂回去让它改。这是 Agent"自我修正"的最小形态。
🛠️
工具
第二步才是真正的手：tool_calls。请求里声明工具清单（名字+参数 Schema），模型不回文本，回"帮我调 get_weather(城市=北京)"——你执行，结果喂回，它继续。
结构化输出: user → 模型 → {"action":"refund"} （交付数据） 工具调用: user → 模型 → tool_calls:[查订单] → 你执行 → 结果喂回 → 模型 → … （驱动行动）
本页知识：结构化输出是"给数据"，工具调用是"下指令"——后者是 Agent 的标志性能力；两者共享同一个底层：Schema 约束 + 本地校验 + 修复循环。案例：llm-unify 完整实现了三档结构化输出与修复循环，是接工具前的必修地基。
器官 4

🔄心脏：Agent Loop Agent 的生命体征

while True: 响应 = 大脑(messages, tools) if 响应.tool_calls: # 模型喊"用工具" 结果 = 执行(响应.tool_calls) # 你来动手 messages += [assistant(tool_calls), tool(结果)] # 观察喂回 continue # 再思考 else: return 响应.content # 不再喊工具 = 任务完成，停机
🔄
心脏
我每跳一轮 = 一次"思考→行动→观察"。停止条件就藏在响应里：模型不再要工具、finish_reason 变成 stop——它自己知道什么时候收工。
🧑‍🏫
讲师
注意循环里被喂回去的不只是文本——工具结果也是上下文。这也是为什么记忆器官那么重要 ↓
本页知识：Agent Loop 是 Agent 的定义性结构；终止权在模型（是否继续要工具）；每一轮都是一次完整的 LLM 调用——所以计费、限流、观测都要按"多轮"设计。案例：llm-unify 是这个循环的"供水系统"，保证每一轮调用都可靠。
器官 5

🧵记忆：上下文窗口经济学 短期 / 长期

🧵
记忆
我的短期记忆就是 messages 列表——每轮对话、每次工具结果都追加进来。代价：窗口有限（token 计费），塞满了就失忆。
🧑‍🏫
讲师
所以记忆管理是 Agent 的长期课题：裁剪（保留最近 N 轮）、摘要（旧对话压缩成一段）、外置（存向量库，用时检索——这就是 RAG，后续课程的主角）。
🧵
记忆
一句话：上下文窗口是 RAM，向量库是硬盘。RAM 贵而快，硬盘大而慢，Agent 要学会分层用。
本页知识：短期记忆=消息累积（有窗口上限与成本）；长期记忆=RAG 检索增强；上下文超限是 Agent 最常见的运行时故障之一（要能识别并处理）。案例：llm-unify 把"上下文超长"识别为独立异常类型并换路由兜底。
器官 6

🎭人设：System Prompt 是 Agent 的宪法 Prompt 工程

🎭
人设
我是 Agent 的行为契约：角色是谁、目标是什么、边界在哪、输出什么格式、遇到异常怎么办——全写在我这里。
🧑‍🏫
讲师
写好我的要素：角色与目标、行为约束（能做/禁做）、输出契约（格式）、示例（few-shot 立标杆）、异常处理（不知道怎么办时怎么办）。
🎭
人设
我很敏感——改一个词，行为就漂移。所以给我配版本管理（只增不改、可 diff、可回滚），不然调优全靠玄学。
本页知识：System Prompt 五要素；prompt 是行为契约不是文案；Prompt 即代码（版本/不可变/回滚）；渲染用户模板要沙箱。案例：llm-unify 的 Prompt 版本库 + Jinja2 沙箱 + StrictUndefined。
器官 7

🦺护栏：概率世界的安全带 注入 / 权限 / 校验

🦺
护栏
大脑是概率的、输入是不可信的、输出是不保证的——三重不确定性，全靠我兜。没有护栏的 Agent 不能上线。
🧑‍🏫
讲师
三层护栏：输入（注入防护——指令和数据都是自然语言，没有语法边界，只能纵深防御：包裹、声明、最小权限）；过程（工具白名单、危险操作确认）；输出（Schema 校验、泄漏扫描）。
🦺
护栏
记住那条安全第一性原理：注入的危害上限 = Agent 手里的权限上限。给工具授权之前，先想最坏情况。
本页知识：Prompt 注入是 OWASP LLM Top 1（无根治，纵深防御）；输出校验是最后防线；权限最小化定义攻击边界。案例：llm-unify 落地输入包裹 + 输出泄漏扫描两道防线。
器官 8 · 案例点题

🦴骨架：Harness，把器官组装成生命 工程层

🦴
骨架
前面七个器官再好，没有我它们只是一堆零件。我叫 Harness（脚手架）：统一调用、多模型路由、重试熔断限流、可观测——让每次心跳（每轮 Loop）都可靠。
用户 ⇄ [骨架 Harness] ⇄ 大脑 ├─ 统一调用协议（换模型=改配置） ├─ 路由与降级（主备/权重/熔断） ├─ 限流与重试（保上游也保钱包） ├─ 可观测（request_id 贯穿每轮心跳） └─ 稳定性：所有器官的共用地基
🧑‍🏫
讲师
llm-unify 这个案例项目，就是一块完整的骨架——2800 行、79 个测试、CLI/HTTP/Web 三种形态。器官会随课程一个个长大，骨架从第一周就要立起来。
本页知识：Harness = Agent 的工程地基；Agent 的可靠性不是模型给的，是骨架给的；每个器官的知识最终都要落回骨架的代码里。
🧭 学习路线：骨架（本周）→ 手与心脏（tool_calls / Agent Loop）→ 记忆（RAG）→ 评测（evals）
